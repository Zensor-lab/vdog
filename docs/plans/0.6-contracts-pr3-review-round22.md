## Findings and required fixes

### F1 [MEDIUM] A reference preflight failure silently discards the operation schema

Verified: `_operation_json_schema_node` (`tools/contracts/api_validate.py`)
ends with a readability probe that walks the whole node with the schema-mode
`resolve_refs` and answers `None` on any failure. Two confirmed consequences:

- A dangling local `$ref` *nested* inside the inline
  `GET /derivatives/{id}` 200 schema (e.g. a sibling
  `allOf: [{"$ref": "#/components/schemas/NotThere"}]` beside the component
  `$ref` plus `required: [new_field]`) makes the probe answer `None`, the
  body is judged by the bare component, and nothing names the defect:
  `check_local_refs` runs only on the media schemas
  (`openapi_check.py:108–112`), the all-response scan reads the response
  member's own pointer and its header map — never nested references inside
  an inline response's schema — and the binding loop compares the top-level
  `$ref` text. The whole run passes on a document whose published response
  schema cannot even be used.
- The same probe over-reads: a node whose `examples` (or any other data
  member) carries a literal `$ref` key is refused as unreadable — reproduced
  at `8d2535a` (`_operation_json_schema_node` returns `None` for
  `examples: [{"$ref": "just some text"}]`) — silently discarding the
  sibling assertions of a perfectly valid schema.

**Fix (implement as specified).** Ask the resolution question where it lives
— the rooted evaluation — and never answer it silently:

- Drop the whole-node `resolve_refs` probe from `_operation_json_schema_node`
  entirely. The node comes back as published whenever its *structure* is
  readable (the isinstance walls and the guarded Reference-Object hop stay);
  whether its schema-position pointers resolve is decided by
  `schema_error_report` itself, which — being the validator — consults
  `$ref` only where it is a keyword and never inside `examples`/`default`/
  `enum` data. That is exactly "resolve references in schema positions only".
- At both node call sites (`_validate_against_component`'s node branch and
  `_validate_error_vector`'s node branch) wrap the report and catch the
  resolution family — `referencing.exceptions.Unresolvable` (the public
  catch the deprecation note prescribes; the rooted path raises its
  `PointerToNowhere` subclass) plus the `_RESOLUTION_FAILURES` pointer set.
  On failure: append an `E.SPEC_COMPONENT_DRIFT` violation located at
  `{entry['id']}: operation schema` naming the unreadable pointer and the
  bound component, *then* judge the body against the component exactly as
  today. An unresolvable component (the fallback target) earns its own
  `SPEC_COMPONENT_DRIFT` at the same vector — never exit 2, never silence.
- The container-level fallback (an unreadable response/requestBody hop) is
  unchanged: those shapes are owned by the checker's scans as today.

### F2 [LOW] A valid fractional `multipleOf` on an operation schema aborts the validator

Verified: pinned jsonschema's `multipleOf` does `quotient = instance / dB`
for a float divisor, and API bodies parse with `parse_float=decimal.Decimal`
by design — `Decimal("64.0") / 0.5` raises `TypeError` (reproduced at
`8d2535a` against the committed derivative vector), so a legal
`multipleOf: 0.5` sibling the body satisfies reaches the CLI as exit 2
"validator internal error" the moment it rides the operation-node path.

**Fix.** In `tools/contracts/schema_docs.py`, give the exact-number validator
class (`DRAFT202012_VALIDATOR`, built by `create(...)` at lines 129–133) a
`multipleOf` keyword that preserves exact arithmetic for `Decimal` instances:
for a `Decimal` instance divide exactly —
`(Fraction(instance) / Fraction(str(dB))).denominator != 1` is the library's
own overflow-fallback arithmetic, and `Fraction(str(...))` is exact for
`int`, `float` and `Decimal` divisors — and yield the library's exact message
`f"{instance!r} is not a multiple of {dB}"`. Every non-`Decimal` instance
delegates verbatim to the library keyword
(`Draft202012Validator.VALIDATORS["multipleOf"]`), so no other instance's
behaviour — including float/float and the overflow fallback — moves. Wire it
as `validators={**Draft202012Validator.VALIDATORS, "multipleOf": _exact_multiple_of}`;
the class-level patch (not a call-site guard) is what keeps the media path,
the component path and the new operation-node path answering one question
the same way.

### F3 [LOW] Array or object values for `kind`/`expected` abort the index reader

Verified: `_load_index` (`tools/contracts/validate.py:383` area) tests
`item.get("kind") not in {"clip", "active", "api"}` and
`item.get("expected") not in {"valid", "invalid"}` — set membership against
an unhashable value (`"kind": []`) raises `TypeError` inside the reader
itself, before the record can earn `FIXTURE_INDEX_INVALID`, and the CLI dies
at exit 2 again — the very class round 21 F3 closed for absent members.

**Fix.** Consult the type before the set: a value that is not a `str` is an
unknown `kind` / invalid `expected` — named `FIXTURE_INDEX_INVALID` exactly
as today, and it stays in the loop only when the loop survives it (present
values survive `str()` in the loop and land in its honest branches; absent
ones stay the round-21 crash shapes that are dropped). Add the unhashable
values to the reader's own regression matrix and an exit-1 CLI pin.
