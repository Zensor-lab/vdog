## Findings (from the reviewer, all confirmed in source at `fa5177e`)

1. **Malformed SHA-256 bypasses integrity validation.** `manifest.files.*.sha256`
   (media_validate.py ~685) and the checksums sidecar (~879) compare only when
   `_LOWER_HEX_64` (`\A…\Z`) matches; a value of 64 hex chars plus a trailing
   `\n` passes the schema pattern `^[0-9a-f]{64}$` (Python `$` matches before a
   final newline) and then silently skips the comparison. Same silent skip for
   missing/malformed `bytes`.
2. **Active segments can exceed 3600 frames.** The frame `seq` maximum
   suppression (media_validate.py:74-77) assumes the manifest `frame_count`
   bound enforces the ceiling, but active records have no `frame_count` and
   `_walk_index` has no independent cap.
3. **Required JSON bodies can be omitted.** Schema validation runs only when
   `_load_body()` returns bytes (api_validate.py:161); a header-only vector can
   claim `PairResponse` etc. and pass. The final empty-vector check (279-291)
   is request-side and headers-free only.
4. **The 16 KiB control-request limit is applied to responses too**
   (api_validate.py:162) — a valid 100-item backend clips page would be
   falsely rejected. `MAX_CONTROL_BODY_BYTES` in bounds.py is documented as a
   request bound.
5. **Non-JSON numeric literals accepted.** `json.loads` (api_validate.py:174)
   defaults to accepting `NaN`/`Infinity`; `"progress": NaN` passes the type
   check and escapes both range comparisons. Fixture writing uses the default
   `allow_nan=True`.
6. **Header validation disagrees with the selected operation.**
   `_rule_content_type` (api_validate.py:803) checks a global set, so a preview
   response with `Content-Type: application/json` passes; and
   `Cache-Control: no-store` — documented for preview in device-v1.yaml
   (~224-227, ~661 `const: no-store`; interfaces.md:106) — has no rule in
   `HEADER_RULES`, so a conforming preview response is rejected.
7. **Clock uncertainty lacks the shared 2^53−1 ceiling.** media section 2
   requires shared integers ≤ 2^53−1, but `uncertainty_ms` carries only a
   minimum in manifest.schema.json:190, active-record.schema.json:111, and
   both OpenAPI mirrors (device-v1.yaml ~1442, backend-v1.yaml ~1809), and
   `_clock_violations` (media_validate.py:809) tests only negativity.
8. **Two required refusals are missing from the frozen API.** `device.pair`
   omits 403 (closed physical claim window; interfaces §1-2) and
   `backend.patch_upload_file` omits 410 (expired upload; interfaces §8) in
   api_model.py; the YAMLs and golden fixtures lack both.
9. **HEAD fixtures carry forbidden bodies.** The three committed
   `head_upload_file-response-401/404/410` vectors ship JSON error envelopes;
   RFC 9110 §9.3.2 forbids any HEAD response content, including errors.

### Completed work

**R1 — an integrity field the validator cannot measure is a defect (`media_validate.py`).**
The manifest files block (now ~693-735) and the checksums sidecar (~920-955) each gained
the two branches that were missing: `_is_int(declared_bytes)` false reports
`MANIFEST_SIZE_MISMATCH` / `CHECKSUMS_SCHEMA` naming the shape it was handed, and a
`sha256` that is not a string or does not match `_LOWER_HEX_64` reports
`MANIFEST_HASH_MISMATCH` / `CHECKSUMS_SCHEMA`. The comparisons stayed where they were, as
`elif` branches, so one value produces exactly one finding. The message goes through the
new `_shape` helper, which names a value by its type and its length — `a 65-character
string '…\n'`, `a str '434'`, `a NoneType None` — so the stray newline that was the whole
hole is visible in the report instead of inferred from a code.
`minLength`/`maxLength: 64` joined the `pattern` in the media schema's
`$defs/sha256` and in both OpenAPI `Sha256` mirrors, so a padded digest is refused by a
consumer that never reaches a comparison.

Four vectors, all media, all single-defect: `manifest-sha-trailing-newline`
(`(MANIFEST_HASH_MISMATCH, MANIFEST_SCHEMA)`), `manifest-size-non-integer`
(`(MANIFEST_SIZE_MISMATCH, MANIFEST_SCHEMA)`), `checksums-sha-trailing-newline` and
`checksums-size-non-integer` (both `(CHECKSUMS_SCHEMA,)`). The two manifest vectors ship
no `checksums.json`, because the sidecar describes the manifest's own bytes and a stale
sidecar would add a defect the vector is not about; `test_invalid_clips_ship_no_checksums_except_the_checksum_vectors`
holds that rule. Six unit cases in `test_a_malformed_integrity_field_is_reported_not_skipped`
cover the same damage on both documents and both properties, and
`test_the_digest_shape_is_pinned_where_the_digest_is_declared` pins the pattern and both
length keywords in the media `$defs/sha256` and in both YAML `Sha256` mirrors, while
`test_the_documents_and_the_bound_table_agree` gained the clock and `UInt53` ceiling rows
beside asserts that no notation may publish a `pattern` without its length pair. The
header schemas (`ETagSha256`, `AcceptRanges`) were
deliberately left alone: `_EXPECTED_HEADER_SCHEMAS` pins those nodes keyword-for-keyword
and the finding here was about declared integrity fields, not published header shapes.

**R2 — the walk owns the 3,600-frame ceiling (`_walk_index`).** The gate sits at the head
of the record loop, before the line is measured or parsed, and returns immediately:
`position >= MAX_FRAMES_PER_CLIP` reports `FRAME_COUNT_MISMATCH` naming the record number.
Placing it before the parse matters — the 3,601st record's `seq` is outside the frame
schema's `maximum`, so a gate after the parse would blame the record for a bound on the
clip. It is one gate for both segment kinds, which is the half the manifest `frame_count`
comparison could never reach: an active record declares no count.

The committed vector `media/invalid/index-records-above-clip-ceiling` is therefore an
*active* segment: 3,601 records at `t_us = i × 33_000`, which keeps the implied duration
under `MAX_SEGMENT_DURATION_US` so the ceiling is the only finding. Unit coverage is the
four-sided pair `test_the_walk_refuses_the_record_past_the_clip_ceiling` — 3,600 valid and
3,601 flagged, for a finalized clip *and* for an active segment — plus
`test_the_committed_over_ceiling_vector_is_an_active_segment`, which pins the kind, the
record count and the absence of `frame_count`.

**R3 — presence is judged before contents (`api_validate.py`).** `_body_presence` runs
after the bytes are loaded and before anything decodes them. A HEAD or a 204 that ships a
body is `FIXTURE_INDEX_INVALID` naming the files, and the body is then dropped so its
envelope is never read: those bytes describe a message no conforming server sends, so the
defect is the index, not the JSON. Every other direction has to ship what the contract
binds — `_required_body_reason` names a request schema, a documented record, or the shared
error envelope for a documented rejection — and answers `API_SCHEMA` when the index names
no body file. Documented non-JSON bodies (the preview stream, the two downloads) are
absent from that list on purpose: their vectors carry headers and status and the bytes are
outside what this gate can judge.

Vectors: `pair-request-missing-body`, `pair-response-201-missing-body` (`(API_SCHEMA,)`
each, headers-only), `upload-head-response-410-with-body` (`(FIXTURE_INDEX_INVALID,)`, no
`api_error_code`). Nine unit cases build their vectors in `tmp_path` through `_vector`,
which writes the same fields `fixtures.json` carries, because a defect about whether a
body exists cannot ride along as a second copy of a committed vector; the three
documented-non-JSON cases assert silence so the new gate cannot be satisfied by refusing
everything.

**R4 — the control ceiling is a request bound.** The gate is now
`if direction == "request":`, which is what `bounds.py` documents and what the receiving
side has to buffer; a response is bounded by the manifest-binding rules and the
`Content-Length` rule instead. `backend/valid/clips-page-response-200-full-page` is a

the committed page's size and silence, and an oversized `PairRequest` still refused with

**R5 — no JSON notation admits `NaN`.** `json.loads(..., parse_constant=_reject_nonfinite)`
in the body decode, and `_reject_nonfinite` raises for `NaN`, `Infinity` and `-Infinity`,

exclusive with `body`, written verbatim by `_build_all`) so the literal
`"progress": NaN` survives into a committed file; it declares `(API_SCHEMA,)`. Unit side:
the same literal in a `tmp_path` vector, `dump_json` raising, and
`test_no_conforming_body_carries_a_non_json_literal`, which reads every committed API
body with the validator's own hook and accepts exactly one offender — that vector, with
that declaration.

**R6 — a media type or a directive is only conforming for the operation that publishes
