## Root cause (verified against the pinned jsonschema 4.26.0 source)

`tools/contracts/schema_docs.py:520–549` `_rooted_validator` builds
`DRAFT202012_VALIDATOR(rooted, format_checker=FORMAT_CHECKER, registry=...)`
— the custom class from `create(...)` at lines 126–130 whose TYPE_CHECKER
admits integral `Decimal` values (`is_json_integer`, lines 106–120).
Reference following goes `jsonschema/_keywords.py:274 ref()` →
`Validator._validate_reference` (`validators.py:459–470`) →
`self.descend(...)` → `self.evolve(schema=..., _resolver=...)`
(`validators.py:402–423`). The `create()`-class `evolve`
(`validators.py:339–348`) selects the class with
`validator_for(schema, default=self.__class__)`, and `validator_for`
(`validators.py:1395–1411`) returns `_META_SCHEMAS.get(schema["$schema"], …)`
whenever the schema spells `$schema` — for the supported 2020-12 dialect that
is the **built-in** `Draft202012Validator`, whose default TYPE_CHECKER
rejects `Decimal('0.0')` as integer. API bodies are parsed with
`parse_float=Decimal` by design, so a valid, supported dialect declaration
silently changes the gate's judgment of valid fixtures.

## Goal

Keep the exact-number (Decimal-aware) integer checker active whenever
reference resolution or schema evolution selects the supported Draft
2020-12 validator, without changing validation outcomes for any other
dialect, without touching any contract document or fixture, and without
restoring any schema-tree pre-expansion on the instance path (the round-19
F1 fix and its annotation-scope/overlapping-pattern tests stay as committed).

## Findings and required fixes

### F1 [MEDIUM] Pin evolve() onto the exact-number validator for the supported 2020-12 dialect

`tools/contracts/schema_docs.py`, immediately after the
`DRAFT202012_VALIDATOR = create(...)` block (lines 123–130).

Decision (implement as specified): override `evolve` on the
`DRAFT202012_VALIDATOR` class so that whenever the library's own class
selection would pick the built-in `Draft202012Validator` (any `$schema`
spelling that `validator_for` maps to that class — the supported dialect),
the custom `DRAFT202012_VALIDATOR` class is selected instead. Every other
library selection is left untouched: a draft-07 `$schema` must still evolve
onto `Draft7Validator` exactly as today. Mirror the library's state copy so
the evolved instance keeps schema, resolver, registry, and format_checker:

```python
from attrs import fields as _attrs_fields          # pinned transitive dep of jsonschema
from jsonschema.validators import validator_for    # public helper

_EXACT_NUMBER_EVOLVE_FIELDS: Final = tuple(
    (f.name, f.alias) for f in _attrs_fields(DRAFT202012_VALIDATOR) if f.init
)

def _evolve_preserving_exact_numbers(self, **changes):
    schema = changes.setdefault("schema", self.schema)
    NewValidator = validator_for(schema, default=type(self))
    if NewValidator is Draft202012Validator:
        NewValidator = DRAFT202012_VALIDATOR
    for attr_name, init_name in _EXACT_NUMBER_EVOLVE_FIELDS:
        if init_name not in changes:
            changes[init_name] = getattr(self, attr_name)
    return NewValidator(**changes)

DRAFT202012_VALIDATOR.evolve = _evolve_preserving_exact_numbers
```

Adapt names/docstrings to the file's voice; document in the docstring why
(§11.3 rooted path, `parse_float=Decimal` bodies, dialect declarations per
OpenAPI 3.1 schema-dialect rules) and extend the round-19 comment above
`DRAFT202012_VALIDATOR` if useful. `attrs.fields(...)` (public attrs API)
replaces the library's private closure-local `evolve_fields`; the class is
the attrs class `create()` returns, so the same init-field list applies.

Rejected alternatives (do not adopt): registering the custom class in
`_META_SCHEMAS` (via `create(version=...)` or direct mutation) — process-wide
global side effect the module comment at lines 123–125 deliberately avoids;
stripping `$schema` from the schema before evolution — fabricates a document
that no longer matches the committed bytes on the report path; deep-copy
tree flattening — reintroduces the round-19 annotation-scope defect this
round's acceptance forbids.
