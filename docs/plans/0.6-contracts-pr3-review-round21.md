## Findings and required fixes

### F1 [MEDIUM] An operation schema node can disagree with the golden fixtures

Verified: the document checker's binding loop reads only the `$ref` string at
an operation's JSON body schema — `_json_schema_ref`
(`tools/contracts/openapi_check.py:1351–1371`) asks `schema.get("$ref")` and
the loop compares the pointer text (`openapi_check.py:534–542`, `589–597`).
The fixture validator evaluates only the referenced component:
`_validate_against_component` validates `components[schema_name]` with the
document as root (`tools/contracts/api_validate.py:589–616`, called for JSON
bodies at `api_validate.py:285`), and `_validate_error_vector` does the same
for `operation.response_schemas.get(status) or "Error"`
(`api_validate.py:635–652`).

Consequence, as the review reproduced: adding `required: [new_field]` beside
the existing `$ref` on the `GET /derivatives/{id}` 200 schema
(`contracts/backend-v1.yaml:655`) leaves both checks satisfied by the same
fixtures — the checker still reads only the `$ref` text, the fixture validator
still judges the bare `DerivativeRecord` component — even though the published
schema (siblings of `$ref` are keywords that apply, JSON Schema §8.2.3.1)
refuses every committed derivative 200 body that lacks the field.

**Fix (implement as specified).** In `tools/contracts/api_validate.py`, judge
the body against the actual operation schema node with the document as its
root — the same rooted `schema_error_report` call the component path already
makes, but handed the node the document's operation publishes rather than the
bare component:

- New guarded reader, e.g. `_operation_json_schema_node(item, document,
  direction, status)`: for a response it walks
  `item["responses"][str(status)]` through the same bounded, cycle-guarded
  one-or-more `$ref` hop semantics the document checker's
  `_shallow_reference`/`_alias_chained_reference` pair use; for a request it
  reads `item["requestBody"]` (resolved through a guarded hop — a body moved
  into `components.requestBodies` answers identically to its inline twin).
  It then reads `content["application/json"]["schema"]` with `isinstance`
  walls at every member. Every unreadable shape — non-Mapping container,
  un-followable hop, missing `application/json`, non-Mapping media entry or
  schema node, a `$ref` that is not a string or does not resolve (guarded,
  with the exception set `check_local_refs` refuses) to a Mapping — answers
  `None`.
- Call sites: the success path (`api_validate.py:282–285`) and
  `_validate_error_vector` (`api_validate.py:635–652`) first ask for the
  node. When it is readable, validate with
  `schema_error_report(node, body, root=document)` — a bare-`$ref` node
  evaluates exactly as the component does today (the rooted validator follows
  the pointer and keeps sibling annotations in document scope, the §11.3
  property the round-19/20 work protects), and sibling keywords beside the
  `$ref` now judge the instance the way any conformant consumer of the
  published contract would read them. When the node is `None`, keep today's
  component validation **byte-for-byte in behaviour**: the document checker
  already names those shapes as document findings, and the vector must still
  be judged against the table-bound component. Keep the existing
  "the contract does not define the schema the index binds" early return
  (`api_validate.py:597–604`, and its error-path twin at `637–644`): the
  component-presence question is asked before the node question.
- Do not touch `openapi_check.py`'s binding loops: "which component does the
  operation bind" stays their question; "does the body satisfy what the
  operation publishes" becomes the fixture validator's.

### F2 [LOW] Malformed OpenAPI containers interrupt the report

Verified: `tools/contracts/openapi_check.py:475` sets
`responses = item.get("responses", {})` and line 477 tests
`str(status) not in responses` — a known operation with `responses: null`
raises `TypeError` on that first membership test, and a top-level
`servers: [null]` raises `AttributeError` while reading
`servers[0].get("url")` at `openapi_check.py:163`. Both reach the CLI as
exit 2 "validator internal error" before the contract findings print.

**Fix.** Follow the round-11/14 container idiom — name the member once, then
read it as declaring nothing:

- `servers`: a declared `servers` that is not a list earns
  `SPEC_STRUCTURE_MISSING` at `{contract}-v1.yaml servers` with detail
  `servers is {type}, not a server array` and is read as `[]`; the existing
  expected-server finding then fires as it always has (two truthful
  statements, as `servers: null` already produces today). A non-empty list
  whose first member is not a Mapping earns `SPEC_STRUCTURE_MISSING` at
  `{contract}-v1.yaml servers/0` with detail `servers/0 is {type}, not a
  server object`, and the expected-server finding fires too (its URL is not
  the expected one). The committed documents are unaffected: they declare a
  one-entry list with the expected URL.
- `responses`: a declared `responses` member that is not a Mapping earns
  `SPEC_STRUCTURE_MISSING` at `{where} responses` with detail
  `responses is {type}, not a response object`, and every later reader — the
  documented-status loop, the undocumented-status loop, both binding loops
  (which bind `None` against their tables), and the all-response scan — sees
  `{}` and names its own consequence, exactly the way the round-11
  non-list `parameters` member is "read as declaring nothing". An absent
  `responses` says exactly what it always said, with no new finding.

No other reader is exposed: `check_headers_contract` reads
`components.headers` alone, and every response read in `openapi_check.py`
funnels through the guarded `_resolve`/`_resolved_response*` helpers already
proven in rounds 12–16.

### F3 [LOW] An incomplete fixture record hides its own diagnostic

Verified: `_load_index` (`tools/contracts/validate.py:294–313`) records
`FIXTURE_INDEX_INVALID` for a bad `expected`, a non-list `files`, or an
unknown `kind` — and then still appends the entry (line 312). The validation
loop at `validate.py:163–183` subscripts `entry["kind"]` (165), `entry["expected"]`
(175), `entry["contract"]` (182) and `entry["category"]` (183), so removing
`kind` from one index entry aborts the run with `KeyError` — exit 2 — before
the recorded finding prints or regeneration is checked. `contract` and
`category` carry no index check at all, and `expected_error_codes` (looped at
line 176) would `TypeError` the loop the same way if declared as a scalar.

**Fix.** Make the index reader the single gate: a record queues into the
validation loop only when every key the loop and validators subscript or
iterate is present and well-typed. Concretely, in `_load_index` change the
`expected`, `files` and `kind` checks from record-and-keep to record-and-
drop (name the record by id, `continue` without appending — the same shape
the absent-`id` and duplicate checks already use), and add the same rule for
`contract` (a non-empty string), `category` (a non-empty string) and
`expected_error_codes` (absent, or a list). Everything the validators reach
through `.get` (`operation`, `status`, `direction`, `schema`, `api_error_code`)
stays their own findings, unchanged. A dropped record still counts once in
`FIXTURE_INDEX_INVALID` and never enters `clip_dimensions` (which reads
`.get` members anyway).

### F4 [LOW] The round-20 fixture assertion does not pin decimal notation

Verified: `tools/contracts/tests/test_contract_documents.py:4118` compares
`body["crop"] == {"x": 0.0, "y": 0.0, "width": 64.0, "height": 64.0}` — in
Python `0 == 0.0`, so regenerating the vector's crop with integer literals
would keep the API and corpus tests green while nothing on the path exercises
decimal-notation parsing any more.

**Fix.** In that test, assert the decoded value types as well as the values:
every `crop` member must be a `float` under the test's plain `json.loads`
(an integer literal decodes to `int` and reddens the test), keeping the
existing equality assertion's message as the pin statement. No fixture
change: the committed vector already carries its window in decimal notation,
and the direct validator tests continue to cover the round-20 fix itself.
