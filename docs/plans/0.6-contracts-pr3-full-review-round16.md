## Goal

Close the review's two P3 checker notes so that (a) a media-type entry whose value is
not an object is named at the member instead of certified, and (b) a JSON success
response or request body declared once in `components.responses` /
`components.requestBodies` and referenced from an operation binds exactly as its
inline equivalent does — no false `binds None`, and the binding check still bites
when a reused component binds the wrong schema. Committed contracts, media schemas,
and fixtures stay byte-for-byte unchanged; no malformed document may reach exit 2.

## Background (self-contained)

The contract suite (`tools/contracts/`) validates `contracts/backend-v1.yaml` and
`contracts/device-v1.yaml` plus 441 golden fixtures against the operation table in
`tools/contracts/api_model.py`. The document checker under attack is
`tools/contracts/openapi_check.py::check_openapi` → `_check_operation`. CI runs
(`.github/workflows/contracts-pr.yml`):

```sh
uv run --python 3.12 --with-requirements tools/contracts/requirements-dev.lock python tools/validate_contracts.py
uv run --python 3.12 --with-requirements tools/contracts/requirements-dev.lock pytest tools/contracts/tests
```

Relevant helper inventory in `openapi_check.py` (line numbers at the base commit):

- `_media_type_map` (L1069) guards the *member* shape (`content` not a Mapping →
  `"is {type}, not a media-type map"`) and is the single read behind five call
  sites: success-binding loop (L388), error-envelope loop (L438), request-body
  publish comparison (L697), response media-type comparison (L743), request-body
  binding branch (L820). It never validates the *values*: `set(content)` and the
  key comparisons read keys only, so an entry `null` or `5` is invisible — F1.
- `_json_schema_ref` (L1110) reads
  `content["application/json"]["schema"]["$ref"]` from the node the caller hands
  it, returning `None` when any step is missing or unshaped; callers render that
  as `binds None instead of {schema}`.
- `_resolved_response` / `_resolved_response_node` (L1000/L1087) run the *full*
  guarded read: `_resolve` (L976) hands any node carrying a top-level `$ref` to
  `schema_docs.resolve_refs`, which (schema_docs.py:271-284) replaces the whole
  `$ref` node and then **recursively inlines every nested `$ref`** in the target.
  So a `$ref`'d response/body arrives with `content.application/json.schema`
  already expanded — the `$ref` the binding question asks about is gone →
  `binds None instead of {schema}` — F2. (An inline node passes through
  untouched, which is why the committed documents, where every bound status and
  every request body is inline, certify today.)
- The error-envelope binding loop (L428-469) already dodged exactly this by
  reading through `_alias_chained_response` (L1043) — one pointer hop via
  `_shallow_response` (L1014) that leaves nested `$ref`s intact, chained while
  the hop itself carries a `$ref` (pure-alias and `$ref`-with-siblings hops,
  refs followed at most once). The response media-type loop (L740) reads through
  the same chain. Round 15 tested that chain (
  `test_a_pure_ref_alias_component_still_publishes_the_table_media_types`); this
  round extends the *binding* reads to it — F2's mandated fix ("the same shallow
  object-reference resolution used for shared error responses").
- `_resolved_request_body` (L982) full-reads `item["requestBody"]` once (L691)
  for the `required` question, the publish comparison, and the binding read; a
  broken chain collapses to `{}` ("not required" + `binds None`), and there is no
  separate readability owner for a requestBody `$ref` — unlike responses, where
  the all-response scan (L488) owns `SPEC_COMPONENT_DRIFT`.

Round-14/15 rules that stay binding:

- No loop may let an unreadable node raise past the CLI: every malformed/dangling
  node earns a finding (exit 1), never exit 2 "validator internal error".
- A shape refusal is named once by its one owner; sibling loops skip or the final
  dedup pass collapses exact `(code, location, detail)` repeats.
- The `requestBody`-own-`required` refusal is independent of its `content` member's
  shape (the `published or body_issue is not None` gate, round 15).
- The shared `Error` envelope stays identical; HEAD/204 bodyless semantics
  preserved.

## Scope (two items + tests)

### Item 1 (P3-1) — validate each media-type entry's shape before comparing keys

File: `tools/contracts/openapi_check.py`, `_media_type_map` (L1069).

After the existing Mapping check on `content`, scan the declared entries (document
order): the first entry whose value is not a `Mapping` returns
`({}, f"media type {name!r} is {type(entry).__name__}, not a media-type object")`.
All five call sites then name the member once through their existing
`content_issue`/`body_issue` branches and skip key comparison/binding reads —
no caller changes needed.

- `{}` stays a valid Media Type Object (OpenAPI 3.1 makes every member optional;
  this is the legal spelling for binary content) — only non-Mapping values are
  refused. Do not go deeper: the shape of `schema`, `example`, `examples`,
  `encoding` members stays out of scope (record as follow-up).
- Keep `_json_schema_ref`'s `isinstance` walls as the last line (its docstring
  already says so); update its docstring only if the wording now misstates who
  owns the refusal.
- The response media-type loop (L740→L756 `published = set(content)`) and the
  request-body publish comparison (L697-714) keep their key-comparison semantics
  for well-shaped entries.
- The `requestBody`-`required` gate at L723 keeps firing beside an entry-shape
  refusal (it already keys on `body_issue is not None`).

### Item 2 (P3-2) — shallow object-reference reads for the two schema-binding loops

File: `tools/contracts/openapi_check.py`.

1. Rename the generic node readers `_shallow_response` → `_shallow_reference` and
   `_alias_chained_response` → `_alias_chained_reference` (mechanical: call sites
   L435/L490/L740/L1058/L1065, docstrings, `:func:` references in the round-15
   comments). They follow local pointers through any node, not just responses,
   and Item 2.3 makes them serve `requestBody` too.
2. Success-binding loop (L381-414): keep the `_resolved_response` call as the
   readability/drift gate (`continue` on `unreadable`, wording unchanged). Take
   both the `_media_type_map` read and the `_json_schema_ref` binding read from
   `_alias_chained_reference(responses.get(str(status), {}), document)`; when the
   chain returns `None`, `continue` — the all-response scan owns that hop, exactly
   as the envelope loop already does (L435-437). Safety argument to preserve in
   the comment: whenever the full read certified the node readable, every
   `None` path of the chain (non-string/non-local pointer, un-followable hop,
   non-Mapping target, repeated ref/cycle) is a shape a guarded full read also
   refuses, so the drift was already named; skipping cannot silently certify a
   binding the scan did not see.
3. Request-body binding branch (L817-838): read `_json_schema_ref` from
   `_alias_chained_reference(item.get("requestBody", {}), document)`; when that
   returns `None`, fall back to the existing full-read `body` (an un-followable
   chain keeps today's honest `binds None instead of …` verdict — a requestBody
   has no readability gate to `continue` to). The `required` read (L818) and the
   `request_schema is None` publish comparison (L691-724) keep reading `body`:
   keys and `required` survive full inlining, and the entry-shape gate reads the
   same values through either node.
4. The envelope loop's binding read (L461) is already shallow-chained — leave it.

No behavior change for any inline declaration (both helpers return an inline
non-`$ref` node unchanged), which is what keeps the committed documents green.
