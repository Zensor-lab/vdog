backend and tools can later consume one set of test vectors:

## Contract decisions (Orchestrator-set; apply verbatim)

1. Media schemas: `contracts/media-v1/frame-record.schema.json`,
   `contracts/media-v1/manifest.schema.json`,
   `contracts/media-v1/active-record.schema.json`, all
   `$schema: https://json-schema.org/draft/2020-12/schema`, `additionalProperties:
   false` on write-side objects, bounds encoded per media-format §2 table
   (size 1–2,097,152; frame count ≤3,600; payload ≤268,435,456; index line
   ≤512 incl. newline; index ≤1,843,200; manifest/active ≤16,384; width/height
   1–1600; nominal_fps 1–30; integers nonnegative ≤2^53−1; `v` const 1;
   SHA-256 `^[0-9a-f]{64}$`; CRC32 `^[0-9a-f]{8}$`; ID patterns below).
2. ID syntax (media §1): `device_id`/`boot_id` `^[0-9a-f]{32}$`; `clip_id`
   `^[0-9a-f]{32}-[0-9a-f]{8}$` and the clip_id boot_id prefix must equal
   `boot_id` (cross-field check is validator logic, not schema).
3. Clock rule: `clock.source ∈ {unknown, phone, sntp}`; when `unknown`,
   `start_utc` and `uncertainty_ms` are both null; when `phone`/`sntp`, both
   are non-null (`start_utc` RFC3339 UTC, millisecond precision, trailing `Z`;
   `uncertainty_ms` integer ≥0). `duration_us` > final `t_us` and ≤120,000,000.
   `close_reason` enum: `duration,size,settings,clock_change,shutdown,
   storage_fault,recovery,ota`; `recovered:true` ⇔ `close_reason:"recovery"`.
   `capture_order` nonnegative integer, gaps allowed.
4. `contracts/device-v1.yaml` — OpenAPI 3.1.0, servers
   `https://vdog.local/api/v1`, covering interfaces §2–§6 routes: `POST /pair`,
   `POST /tokens/revoke`, `GET /capabilities`, `GET /status`, `GET /settings`,
   `PUT /settings`, `POST /time`, `GET /preview` (documented
   `multipart/x-mixed-replace`, not schema-validated bodies), `GET /clips`,
   `GET /clips/{clip_id}/manifest`, `POST /clips/{clip_id}/leases`,
   `PUT /leases/{lease_id}`, `DELETE /leases/{lease_id}`,
   `GET /clips/{clip_id}/files/{name}` (ETag/Range/If-Match/412/416/410 rules
   as documented responses/headers), `POST /ota`, `POST /events`, `GET /events`,
   `DELETE /events/{event_id}`.
5. `POST /ota` request body is `application/octet-stream` with description
   "signed envelope; encoding and `contracts/ota-v1.json` deferred to package
   2.10; consumers must not guess"; include `x-deferred: "2.10"` on the
   operation. No OTA schema file.
6. `contracts/backend-v1.yaml` — OpenAPI 3.1.0, servers
   `https://backend.local/api/v1`, covering §7–§9: `POST /tokens`,
   `DELETE /tokens/{id}`, `POST /devices`, `GET /devices`, `GET /clips`,
   `GET/DELETE /clips/{clip_id}` (+`device_id` query), `GET /clips/{clip_id}/files/{name}`,
   `POST /uploads`, `HEAD/PATCH /uploads/{id}/files/{name}`,
   `POST /uploads/{id}/commit`, `GET/DELETE /uploads/{id}`,
   `POST /events`, `GET /events`, `DELETE /events/{id}`, `POST /jobs`,
   `GET /jobs/{id}`, `DELETE /jobs/{id}`, `GET /derivatives/{id}`,
   `GET /derivatives/{id}/file`, `DELETE /derivatives/{id}`,
   `GET /health/live`, `GET /health/ready`.
7. Shared conventions in both specs: top-level `v:1` required on request and
   response objects; error envelope `{v,error:{code,message,retryable,request_id}}`
   as one reusable schema; documented status set 400/401/403/404/409/410/413/
   416/422/429/503 where the spec assigns them; cursor ≤256 chars;
   limit default 50 (device)/100 (backend), max 100; name enums
   (`video.mjpg|frames.jsonl`), state/fault-code/job-state/close-reason enums
   exactly from the specs; token/secret patterns `^[A-Za-z0-9_-]{43}$`
   (32-byte base64url, unpadded); `manifest_base64url` pattern
   `^[A-Za-z0-9_-]+$` with decoded-length ≤16,384 enforced by the validator;
   PATCH chunk `Content-Length` documented 1–1,048,576; upload offsets
   `{"video.mjpg":N,"frames.jsonl":N}`.
   Where interfaces.md is silent, choose the least-restrictive permissive
   structure and note it in `contracts/README.md` under "Illustrative choices";
   never invent new required fields or error codes.
8. Fixture layout (committed bytes, deterministic):

   ```text
   contracts/fixtures/
     fixtures.json                 # index: id, kind, path(s), expected(valid|invalid+reason codes)
     media/valid/...               # see AC-02 set
     media/invalid/...             # see AC-03 set
     device/valid/..., device/invalid/...
     backend/valid/..., backend/invalid/...
   ```

   Every fixture is either a passing test vector or a labeled negative vector;
   `fixtures.json` records each one's expected outcome and, for invalid ones,
   the expected validator error code(s). No "example only" files.
9. Fixture invariants: valid clip fixtures contain real JPEG bytes generated
   once by `python -m tools.contracts.generate_fixtures` (Pillow, 64×64
   grayscale, distinct per frame), real CRC-32/ISO-HDLC per frame (equals
   `zlib.crc32` output), real SHA-256 over exact `video.mjpg`/`frames.jsonl`
   bytes, `checksums.json` beside each valid clip recording all three file
   hashes and sizes. Regeneration must be byte-identical (validator checks
   committed fixtures against freshly generated bytes in a temp dir).
10. `tools/validate_contracts.py` is the CLI (thin shim onto
    `tools.contracts.cli`), no arguments, no network, deterministic stdout
    summary, exit 0 only if every check passes, exit 1 otherwise, exit 2 on
    internal error. It checks at least: schemas are valid 2020-12 documents
    (jsonschema meta-schema); OpenAPI files parse as YAML and contain the
    required paths/components (structural assertions); every `fixtures.json`
    entry resolves; valid media fixtures pass schema + media invariants
    (seq continuity, offset continuity `prev.offset+prev.size`, final end ==
    payload size, per-frame CRC over exact bytes, `t_us` first=0 and strictly
    increasing, every bound, JPEG SOI/EOI + Pillow decode + SOF dims match
    manifest, ID syntax + clip/boot prefix equality, hashes vs `checksums.json`,
    index line ≤512B, LF-only, no BOM/blank lines, manifest/active ≤16KiB);
    valid API fixtures validate against the OpenAPI component schemas and
    common conventions (`v:1` present, error shape); invalid fixtures fail
    with the expected error code(s) — a passing invalid fixture is a validator
    error.
11. Toolchain: mirror `tools/firmware` exactly — `tools/contracts/
    requirements-dev.in` (`pytest`, `jsonschema`, `pyyaml`, `Pillow`) compiled
    with `uv pip compile --generate-hashes --python-version 3.12` to
    `requirements-dev.lock`; qualified interpreter is uv CPython 3.12 (system
    3.14 is not qualified). Documented commands:

    ```sh
    uv run --python 3.12 --with-requirements tools/contracts/requirements-dev.lock \
      python tools/validate_contracts.py
    uv run --python 3.12 --with-requirements tools/contracts/requirements-dev.lock \
      pytest tools/contracts/tests
    ```

12. `docs/validation.md` §4: replace `python3 tools/validate_contracts.py`
    with the qualified `uv run` command above and note it exists with HOST
    evidence after this package; keep every other command line intact.

## Acceptance criteria (observable; reviewer + test engineer check each)

- AC-01 Both qualified commands exit 0 on the handoff commit; output names
  every fixture and category. Tool versions recorded (uv/CPython 3.12,
  jsonschema/pyyaml/pytest/Pillow versions from the lock).
- AC-02 Valid media coverage: baseline clip (≥3 frames), gap fixture (large
  `t_us` jump), unknown-UTC, known-clock (phone), early close
  (`close_reason:"size"`), recovered prefix (`recovered:true`,
  `close_reason:"recovery"`), and `active.json` valid vector; JPEGs decode and
  SOF dimensions match manifest; all CRC/SHA values are real.
- AC-03 Invalid media coverage (each rejected with its expected code): bad
  CRC, truncated payload, truncated index (non-final-line truncation plus
  valid-prefix boundary), nonconsecutive `seq`, nonmonotonic/duplicate
  `t_us`, first `t_us`≠0, `duration_us` ≤ final `t_us`, `duration_us`
  >120,000,000, frame size 0 and >2,097,152, index line >512B, oversized
  dimensions (>1600), SOF/manifest dimension mismatch, invalid ID syntax,
  clip/boot prefix mismatch, `v:2` unsupported version, manifest >16,384B,
  unknown `close_reason`, `recovered`/`close_reason` disagreement, offset+size
  overflow past payload end and past 2^53−1 (boundary arithmetic test).
- AC-04 Device API coverage: valid+invalid vectors for pair (success,
  `ALREADY_OWNED` 409, bad secret), tokens/revoke, capabilities, status
  (all 8 states exercised across fixtures, nullable battery/external_power,
  unmounted storage nulls), settings GET/PUT (`REVISION_CONFLICT` 409,
  unsupported profile 400), time (valid RFC3339 ms `Z`, invalid), clips page
  (cursor ≤256, `CURSOR_EXPIRED` 409, limit>100 400), leases (201 300s,
  `LEASE_LIMIT` 409, renewal, `STORAGE_PRESSURE` 409, `LEASE_EXPIRED` 409,
  DELETE 204), files (206+`Content-Range`/ETag/`Accept-Ranges` structural
  vector, `CONTENT_CHANGED` 412 via If-Match mismatch vector, 416 multi-range
  rejection, `CLIP_GONE` 410), events (valid pin set, >10 clips 400,
  `PROTECTION_QUOTA` 409, idempotency collision 409), error envelope shape.
- AC-05 Backend API coverage: tokens/device registration, uploads init
  (valid unpadded base64url of an actual committed `manifest.json`; encoded
  >32KiB 413; decoded >16KiB 422; wrong base64url alphabet 400;
  `Idempotency-Key` mismatch 409), PATCH chunk (valid 204 + offset, wrong
  offset 409 with authoritative offset, bad hash 422, empty/oversized body
  400/413, disallowed name 400), commit (201 `stored`, repeat-commit
  idempotent, integrity 422), `CLIP_ID_COLLISION` 409, HEAD offsets, DELETE
  410 expired, jobs (types/preset enum, states, progress nullable),
  derivatives, health, pagination/error conventions.
- AC-06 Range/lease/upload and time/CRC/hash/version/ID/boundary/overflow/
  error categories each appear in `fixtures.json` (AC-02–05 map onto them).
