## 4. Part A — desk work (start immediately; BUILD/HOST evidence only)

A1. **Portable memory interface** — new `firmware/core/vdog_mem.{h,c}`
(pure C11, no ESP-IDF headers, `extern "C"` guard, same conventions as
`vdog_board.{h,c}`; consumed by `native` via `lib_deps ./core` and by the
target through the existing `components/vdog_board` wrapper or a sibling
component):
- `vdog_mem_detected_t`: flash size/mode/freq + PSRAM size/mode/speed with a
  per-field explicitly-set bitmask (missing ≠ zero, same discipline as
  `vdog_board_profile_t`).
- `vdog_mem_check_baseline(const vdog_mem_detected_t *)` comparing against
  the documented XIAO ESP32S3 Sense build baseline (8 MiB flash QIO/80 MHz,
  8 MiB **octal/OPI** PSRAM 80 MHz): `VDOG_OK` or specific codes with
  `vdog_mem_error_field()` — and named rejects for the wrong-board classes the
  acceptance calls out (quad-only PSRAM, 4 MiB flash, no-PSRAM,
  Plus/N16R8-shaped reports).
- `vdog_mem_format_detected(char *buf, size_t)` — report string with
  `vdog_format_version` buffer semantics (NULL/size rules; unspecified on
  error).
A2. **Recovery/identity interface (portable logic)** — new
`firmware/core/vdog_recovery.{h,c}`:
- boot-mode enum + `vdog_recovery_classify(const char *rom_line)` mapping the
  ROM/EDL lines the 1.2 drill will print (USB-JTAG/serial boot, download
  mode, normal boot) to states; unknown → UNKNOWN, never guessed.
- `vdog_identity_format(vdog_identity_t*, char *buf, size_t)` composing the
  **sanitized** identity line: chip model/revision + configured flash/PSRAM
  summary + `mac_redacted` = only the OUI-independent tail (last 2 bytes
  hex) — never full MAC, never eFuse raw values, no serial numbers beyond a
  caller-supplied opaque board tag. NULL/size semantics as above.
A3. **IDF adapters + main.c** — `components/vdog_board` (or new
`components/vdog_board_hw/`): `vdog_mem_detected_from_sdkconfig()` (#ifdef
discipline like 1.1), `vdog_mem_read_detected()` wrapping
`esp_chip_info`/`esp_psram_get_size`/`esp_flash_get_size` (compiled,
executed only in Part B), `vdog_identity_read_esp()` using eFuse **public
summary only** via helper APIs (no raw reads). `main.c` gains one
`vdog_mem_format_detected` + one `vdog_identity_format` log line after the
1.1 board line. No peripheral/strap writes; **no microphone
initialization**; GPIO21 stays untouched/unclaimed (SD-CS/user-LED sharing
unresolved).
A4. **Host tests (native Unity only — no Python framework in `firmware/`)** —
new `test_vdog_mem` + `test_vdog_recovery` suites: baseline pass; each named
reject (quad-only PSRAM, 4 MiB flash, no PSRAM, N16R8-shaped); missing-field
vs wrong-value; report exact/exact-fit/too-small/NULL; boot-mode classify
cases incl. unknown-input; sanitizer cases proving MAC tail-only rendering
and no secret fields leak. `pio test -d firmware -e native` remains the only
host harness; keep `-Wall -Wextra` clean in both envs.
A5. **Gate fidelity (only if A1–A3 need it)** — extending
`check_board_config.py`/`check_core_purity.py` is allowed ONLY with the same
source-cited fidelity bar set in 1.1 §10/§12 (universal-newline `_split_universal`,
`#error`-guard backstop, no `splitlines()`/`\s` regressions) and must not
weaken any existing regression (45-case out-of-tree harness re-run green).
A6. **Docs** — `docs/hardware-identity.md`: template tables for unit identity
(base-board markings, Sense expansion board, camera module + ribbon, flash
part marking, PSRAM marking **to be transcribed from owner photos**, board
revision determination), plus a "sanitized device report" section (mem line,
identity line, boot-mode drill transcript summary) — every device-derived
row starts as `PENDING`. `docs/bench-assignment.md`: the bounded record —
unit = owner's XIAO ESP32S3 Sense (identity PENDING photos), firmware commit
= `957b415`+1.2 tip, host = this Mac (macOS 26.6.2 25G83 arm64, PlatformIO
Core 6.2.0, bundled Python 3.12, host python3 3.14.6), power = **USB from the
Mac, battery physically disconnected**, authorized operations = **app-image
upload + serial monitor (115200) + port re-identification** (before every
operation: `ls /dev/cu.*` before/after attaching, record the exact
`/dev/cu.usbmodem*` path in the record; flashing targets ONLY that port),
forbidden = erase/erase-flash, eFuse writes, format, NVS overwrite,
filesystem upload, battery wiring/charging, monitor beyond the recorded
session. `docs/toolchain.md` addendum (Part A commands/exit codes/counts +
the Mac inventory re-confirmation). `implementation-plan.md` 1.2 status →
