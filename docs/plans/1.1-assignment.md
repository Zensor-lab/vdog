## 4. Design (authoritative for this package)

1. **Portable board profile core** — new `firmware/core/vdog_board.{h,c}`
   (pure C11, no ESP-IDF headers, C++-consumer-safe exactly like
   `vdog_core.{h,c}`; consumed by `native` via `lib_deps ./core` and by the
   target via a new `firmware/components/vdog_board/` IDF component wrapper
   mirroring `components/vdog_core/CMakeLists.txt`):
   - `vdog_board_profile_t`: target chip id, board id string, flash size
     (bytes), flash mode/freq, PSRAM present/mode/speed, partition-table
     filename, plus a `field_set` bitmask so every field is **explicit** —
     a missing (never-configured) key is distinguishable from a wrong value.
   - Expected-provisional profile constant for `vdog_xiao_sense_proto`:
     target `esp32s3`, board `seeed_xiao_esp32s3`, 8 MiB QIO/80 MHz flash,
     8 MiB **octal (OPI)**/80 MHz PSRAM, `partitions/vdog_8mb_two_ota.csv`
     (matches `sdkconfig.defaults`; the values are build configuration, not
     detected hardware — DEVICE proof stays in 1.2–1.4).
   - `vdog_board_validate(const vdog_board_profile_t *)` returning
     `VDOG_OK` or a specific code (`VDOG_ERR_BOARD_MISSING_FIELD`,
     `VDOG_ERR_BOARD_UNSUPPORTED_TARGET`, `..._FLASH`, `..._PSRAM`,
     `..._PARTITIONS`, `VDOG_ERR_INVALID_ARG`) **plus**
     `vdog_board_error_field()` naming the offending field — the
     "unsupported board / silently defaulted setting fails clearly" logic,
     host-testable.
   - `vdog_board_report(char *buf, size_t)` composing
     `vdog <MAJOR.MINOR.PATCH-SUFFIX> board=<id> target=esp32s3 flash=8MB-qio-80m psram=8MB-opi-80m`
     from the validated profile and the existing `VDOG_VERSION_*` constants;
     buffer/NUL semantics identical to `vdog_format_version` (error codes
     `VDOG_ERR_INVALID_ARG` / `VDOG_ERR_BUFFER_TOO_SMALL`; unspecified buffer
     on error).
   - **No GPIO/pin driving anywhere.** A `PROVISIONAL` comment block may
     *reference* `hardware/prototype-a/pin-map.csv` and must note the
     GPIO21 SD-CS/user-LED sharing is unresolved and that 1.1 code drives no
     pin.
2. **Build-time gate** — new `firmware/scripts/check_board_config.py`, wired
   as an `extra_scripts post:` of **`[env:vdog_xiao_sense_proto]` only**
   (same wiring style as `scripts/gen_build_meta.py`; must not load in
   `native`, and must stay compatible with the test-build redirection done by
   `scripts/test_build_isolation.py`):
   - Reads `.pio/build/vdog_xiao_sense_proto/config/sdkconfig.json` after the
     build and asserts each required key is **present** and equal to the
     expected value: `IDF_TARGET`, `ESPTOOLPY_FLASHSIZE_8MB`,
     `ESPTOOLPY_FLASHMODE_QIO`, `ESPTOOLPY_FLASHFREQ_80M`, `SPIRAM`,
     `SPIRAM_MODE_OCT`, `SPIRAM_SPEED_80M`, `PARTITION_TABLE_CUSTOM`,
     `PARTITION_TABLE_CUSTOM_FILENAME`, `ESP_CONSOLE_USB_CDC`,
     `ESP_CONSOLE_SECONDARY_NONE`, plus `board == seeed_xiao_esp32s3`.
   - Missing key ≠ default: absent or mismatched key → `env.Exit()` (non-zero)
     with a message naming the key, expected and actual. Keep this script a
     thin reader/comparator over an EXPECTED table; the *decision logic* is
     the C validator (single source of truth for semantics).
   - New `firmware/scripts/check_core_purity.py` (same post wiring or chained):
     scans `firmware/core/**` for forbidden tokens (`esp_`, `esp_camera`,
     `sdmmc`, `driver/`, `freertos`, `nvs`, `#include <...IDF...>` forms) and
     fails with the offending file/line — mechanical proof the portable core
     stays camera/SD/IDF-free.
3. **Target-side adapter + version reporting** — `components/vdog_board/`
   provides `vdog_board_profile_from_sdkconfig()` guarded by `#ifdef
   CONFIG_*` so unset keys map to "field not set" (never inherited defaults);
   `src/main.c` logs (still BUILD-only, no peripherals): the existing version
   + build identity lines, then `vdog_board_report()` on success or
   `ESP_LOGE("board config rejected: %s (field %s)")` on failure. No behavior
   change to the OTA-rollback mark or the 0.2 link-time camera qualification.
4. **Host test harness (minimal)** — extend `firmware/test/test_vdog_core/`
   (or add `test_vdog_board/` if cleaner) with Unity cases: validate accepts
   the expected profile; each specific failure (wrong target/flash/mode/PSRAM
   mode/PSRAM absent/partitions/missing field) returns its exact code and
   field name; report string exact-match + exact-fit + too-small + NULL
   cases; a C++ consumer smoke case for the new header (mirror
   `cpp_smoke.cpp`). `pio test -d firmware -e native` stays the only host
   harness — no new test runner, no Python test framework added to `firmware/`.
5. **Docs** — new `firmware/README.md` (environments, root commands, what the
   post-build gate enforces, BUILD vs HOST reporting discipline);
   `docs/toolchain.md` addendum recording: exact commands run, exit codes,
   test counts, the Mac inventory (macOS 26.6.2 build 25G83, Apple silicon
   arm64, PlatformIO Core 6.2.0, PlatformIO-bundled Python 3.12, host
   `python3` 3.14.6), and a pointer that PSRAM/flash values are build-config
   proof pending 1.2 DEVICE checks; `docs/plans/implementation-plan.md` 1.1
   status line updated by the developer from the handoff state.

## 12. Risks and limitations

**Component-interface scope decision (lead note, 2026-11-27):** the plan §1.1
step "component interfaces" is satisfied by the two interfaces this package
actually implements and host-tests — `vdog_core` (version) and `vdog_board`
(identity/validation/report) — plus the enforced core-purity boundary. Empty
interface headers for the **camera, storage and clock** modules are
**deliberately deferred to 1.3, 1.4 and 1.9 respectively**, where each ships
together with its implementation, host fakes and tests. Authoring them now is
rejected: with 0.3 wiring unapproved (candidate pin map, unresolved
GPIO21 SD-CS/user-LED sharing) there is no qualified evidence to freeze those
contracts on, and speculative headers would either drift silently in
1.3/1.4/1.9 or hard-code wrong pins/bus settings the purity gate cannot
detect. This matches master-plan §1.1 and the AGENTS.md rule against inferred
contracts.

**Reviewer-approved deferrals (round 1) → package 1.2:** (a) **F6** —
`check_board_config.py` calls `Import("env")` inside `_scons_main()` instead of
at module level the way `gen_build_meta.py` does; purely stylistic, and both
modes are behaviourally verified (SCons exec injects `Import` into the module
globals; the CLI branch proves the routing decision), so no rework was
warranted at this boundary. (b) **F7(b)** — the SCons-mode/poisoned-file
scenario drivers stay out-of-tree evidence because plan §4.4 bars a Python test
framework under `firmware/`; they should be rehomed in the lead-owned
`tools/firmware` pytest suite (0.9 tools) rather than duplicated here. No
in-scope code is untested as a result: the gate's registered-action behaviour
is additionally proven by the green BUILD run and the `[SKIPPED]` embedded test
build.

- The board report/rejection log path has never executed (no device). Its
  logic is host-tested; the console rendering and `CONFIG_*` reality on the
  unit are 1.2–1.4 DEVICE checks. The gate only proves the build was
  *configured* for 8MB flash / 8MB OPI PSRAM; `CONFIG_SPIRAM_TYPE_AUTO` means
  capacity is still runtime-detected.
- `vdog_board_error_field()` is last-error global state (documented,
  single-threaded boot/diagnostic use). A future multi-task diagnostics use
  must call validate and read the field back-to-back, or take an out-parameter
  refactor.
- The board id string is declared in `components/vdog_board/CMakeLists.txt`
  and independently expected by `scripts/check_board_config.py`; that is two
  places by necessity (no Kconfig board key exists). They cannot drift
  silently — the gate fails the build if `$BOARD` differs — but a deliberate
  board change must update both.
- The purity scanner is token/regex based, not a parser: it is a strong
  tripwire for `esp_*`/RTOS/camera/SD/`nvs`/SDK includes in `core/`, not a
  proof of link-independence (the `native` build is the real link proof).
- The board gate deliberately does not fire for `__test`/`nobuild`/`clean`
  runs, so embedded test images are not configuration-gated (same trade-off
  `gen_build_meta.py` makes for release identity).
- `149597/61124` text/data grew over the 0.2 baseline (`148313/60356`) by the
  board-report code; slot margin remains ≈14.9× (requirement ≥4×).
- 0.3 wiring and 0.7 bench approval are still outstanding: nothing in this
  package may be read as pin approval, and the GPIO21 SD-CS/user-LED sharing
  stays unresolved.
