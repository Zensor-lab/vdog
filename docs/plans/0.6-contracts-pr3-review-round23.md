## Finding and required fix

### F1 [MEDIUM] A same-instance reference cycle on the inline operation schema aborts the corpus check

Round 21 asked the readability question with `resolve_refs`, whose schema
mode "expands a reference cycle once and then refuses" — a cycle surfaced as
a `ValueError` inside `_RESOLUTION_FAILURES` and the vector fell back to the
component. Round 22 deleted that preflight (correctly — it also refused
`examples` that merely quote `$ref`), moving the question into the rooted
`schema_error_report`. The standard library happily follows a pointer that
returns to an in-flight schema and recurses until Python raises
`RecursionError`; the round-22 catch tuple
(`Unresolvable, ValueError, KeyError, IndexError, TypeError`) does not name
it, so a document whose inline response references itself now kills the whole
run instead of producing a finding — one step worse than the round-21
behaviour the reviewer accepted.

**Fix (implement as specified).**

- Extend `_RESOLUTION_REPORT_FAILURES` (`tools/contracts/api_validate.py`)
  with `RecursionError`. Both node call sites already route anything the
  helper reports as un-followable into a named `SPEC_COMPONENT_DRIFT` — the
  operation-node branch charges `{id}: operation schema` and falls back to
  the component, the component branch charges
  `{id}: components/schemas/{name}` and stops — so the cycle joins the
  existing family with no new diagnostic code (`CODES` stays 105).
- In `_rooted_schema_errors`, give the recursion case its own words instead
  of the library's repr: a `RecursionError` means the pointer chain revisits
  an in-flight schema without consuming the instance, so the reason text
  must say `reference cycle` (the pointer itself is deep in the stack and
  not recoverable from the exception). Non-recursion members keep the
  current `f"$ref cannot be followed: {error!r}"` text.
- No other behaviour moves: an instance-consuming recursion
  (`{"$ref": "#/..."}` to a schema that validates a finite instance while
  descending a property) is legal JSON Schema and must still evaluate
  normally — only this *report call* raising `RecursionError` is renamed.
  The container hop (`_follow_reference_hops`) keeps its own round-21
  visited-set refusal; the media path is untouched.
