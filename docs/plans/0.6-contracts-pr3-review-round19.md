## Findings and required fixes

### F1 [MEDIUM] Instance validation must keep `$ref` siblings in schema scope

`tools/contracts/schema_docs.py:355–358`: the round-18 transformation returns
`{"allOf": [resolved, siblings]}` for a `$ref` node with siblings. That is not
equivalent to a Schema Object containing `$ref` plus sibling keywords:
`unevaluatedProperties` (and `unevaluatedItems`, same scoping dependency)
observe annotations from *adjacent* applicators in their own scope
([JSON Schema 2020-12 §11.3](https://json-schema.org/draft/2020-12/json-schema-core#section-11.3)),
and two independently validated allOf branches do not preserve that
relationship. Reproduced on the actual contract: `PairRequest` =
`{"$ref": "#/components/schemas/ReviewPairBase", "unevaluatedProperties": false}`
over a copy of the real `PairRequest` — a standard Draft 2020-12 validator
with the complete local reference root reports **zero errors** for the valid
pair request; the expanded schema reports all three fields unevaluated and the
corpus run fails the committed valid fixture (441/2/PASS=False).

Decision (implement as specified): stop rewriting schema trees on the
instance-validation path. Route the API validation through the standard
library with an offline local reference registry so `$ref` evaluation and
sibling keywords keep their proper schema scope:

- `jsonschema==4.26.0` ships `referencing==0.37.0`; both are in
  `tools/contracts/requirements-dev.lock` (offline-resolvable, no network).
- Give `schema_error_report` (schema_docs.py:425) an optional keyword-only
  `root` parameter (default `None` = today's behavior for every existing
  caller). When `root` is given, build `DRAFT202012_VALIDATOR` (the Decimal
  integer branch class — keep it) over the **raw** (unexpanded) schema node
  with a `referencing.Registry` whose single resource at base URI `""` is
  `root`, so `#/…` pointers resolve against the whole document offline and
  never leave the machine. Preserve the `(property, keyword, message)` report
  shape, sorting, and message truncation exactly.
- Update the two API-path call sites that pre-expand
  (`api_validate.py:605` `_validate_schema_body`, `:641`
  `_validate_error_vector`) to pass the raw `components[schema_name]` node
  plus `root=document` instead of `resolve_refs(...)`. For consistency route
  the third `api_validate.py` validation (`:1546`, manifest) the same way
  when its document root is at hand; `media_validate.py` receives bare
  mappings with no root in scope and keeps `root=None` behavior.
- Leave `resolve_refs`/`resolve_reference` and their tree rules for the
  structural consumers that need them: canonical renderings
  (`openapi_check.py:217,238,250`), reference-mode gate readers, and the
  media-path callers. Do not change reference-mode sibling stripping, the
  cycle policy, or the allOf rewrite — those readers never validate an
  instance against the expanded tree.
- `schema_docs.resolve_refs` docstring and the round-18 plan's claim that
  splitting target and siblings into `{"allOf": [target, siblings]}` is an
  "exact conjunction" must be corrected: it is a conjunction, but it is *not*
  annotation-scope-preserving for `unevaluatedProperties`/`unevaluatedItems`
  (§11.3). Annotate the round-18 plan bullet as superseded by this plan
  (follow the round-17 correction convention).

### F2 [LOW] Scan the effective target's header map behind decorated aliases

`tools/contracts/openapi_check.py:563–596` (all-response scan): the header
name map is read from `_shallow_reference`'s one-hop node even when that node
is itself a Reference Object. A `headers` member beside a `$ref` is ignored
sibling decoration — the effective headers belong to the referenced target.
Both directions are broken (reproduced): `ETag`+`etag` inside a shared
`components/responses/ReviewClip200` earns one `SPEC_STRUCTURE_MISSING` when
referenced directly, but referencing an alias
`{"$ref": "#/components/responses/ReviewClip200", "headers": {}}` reports
zero findings; and a dangling `X-Ignored` header inside that ignored sibling
produces a false `SPEC_COMPONENT_DRIFT`.

Decision (implement as specified): in the all-response scan only, when the
shallow node is itself a Reference Object (`"$ref" in shallow`), treat its
`headers` member as inert decoration — the scan must read the **effective
target's** header map (`resolved_response["headers"]`, the full-resolution
read the scan already computes) and must not attribute findings to members
that live only in the ignored sibling. This makes the
`"headers" not in shallow` two-hop branch (lines 597–616, which already reads
`resolved_response`) the effective path for decorated aliases: shape verdicts
for the target's map travel with it. Keep per-header attribution for genuinely
unreadable target headers: when the target's own header map fails resolution,
the existing per-header loop (or the response-level drift when the map itself
is unreadable) must name the real failing member — an alias's `headers: {}`
must not turn an unreadable target map into a silent pass. Do **not** change
`_shallow_reference` itself (it is the shared contract of the media-type and
binding reads with the densest pin cluster).

### F3 [LOW] A malformed components container is a document failure, not exit 2

`tools/contracts/openapi_check.py:163–164` (and the four sibling sites
verified in round 18's deferred R1-F7 note: `openapi_check.py:214, 244, 265,
1420`, plus `api_validate.py:596, 630`): `document.get("components", {})`
returns `None` (or any non-mapping) when the document declares
`components: null`, and the following `.get(...)` aborts with
`AttributeError` → CLI exit 2 "validator internal error" for both documents.

Decision (implement as specified): validate component-container shapes before
dereferencing them and pass only usable mappings to downstream component
readers:

- When `document.get("components")` is present but not a `Mapping`, name one
  `SPEC_STRUCTURE_MISSING` finding at `components` (message like `components
  is <type>, not a component container`) once, from the document-level check
  in `check_openapi`, and let every downstream reader treat the unusable
  value as empty (`{}-via-isinstance`, e.g. one small shared guard helper) so
  the existing named findings ("Error envelope missing", schema-not-defined
  drifts, bearerAuth-not-defined) fire normally. Absent `components` keeps
  today's exact behavior (no new finding beyond what already fires).
- Sub-containers (`schemas`, `headers`, `securitySchemes`): a non-mapping
  value must be read as empty by the same guard, never crash.
- Tests must cover **both** `device-v1.yaml` and `backend-v1.yaml` through
  the complete CLI on a temporary copy: exit code 1, at least the named
  `components` finding present, no traceback on stderr. Add at least one
  sub-container case (e.g. `schemas: null`) proving a named finding rather
  than a crash.

### F4 [LOW] The OTA deferral gate must see refs under schema applicators

`tools/contracts/openapi_check.py:384` (`check_ota_deferral`): the gate tests
only whether `$ref` is a *direct* member of the octet-stream media entry or of
its `schema`. `schema: {"$ref": "#/components/schemas/VersionedRequest"}`
earns one `OTA_DEFERRAL_MISSING`, but the same reference wrapped as
`schema: {"allOf": [{"$ref": "#/components/schemas/VersionedRequest"}]}` is
legal-OpenAPI schema content, is still a schema reference, and reports zero
findings (corpus stays 441/0/PASS). This is the queued R3-N2.

Decision (Orchestrator ruling — enforce the deferral fail-closed): the
deferred body may not reference a request schema at all, so replace the
direct-member test with a recursive scan of the octet-stream media entry:
walk every nested `Mapping`/`Sequence` member of the entry (its `schema`
member included — the entry-position `$ref` test is subsumed but keep its
message) and if any mapping anywhere in that subtree carries a `$ref` member,
report the existing `OTA_DEFERRAL_MISSING` at `POST /ota requestBody schema`
with the verbatim message "no request schema may be referenced while the
encoding is deferred". Guard non-mappings as today (the `in`-over-scalar
crash stays refused). The scan runs on the un-inlined entry (the alias-chained
read the gate already uses); it walks a finite document tree, so no cycle
budget is needed. Do not define the deferred OTA envelope.
