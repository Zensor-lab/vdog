## Findings and required fixes

### F1 [MEDIUM] `$ref` siblings must conjoin, never overwrite target keywords

`tools/contracts/schema_docs.py` `resolve_refs` (~lines 286–315) merges
`{**resolved, **siblings}`, so a sibling `pattern`/`minimum`/`required`/
`properties` silently replaces the referenced assertion. JSON Schema 2020-12
§8.2.3.1 evaluates both (<https://json-schema.org/draft/2020-12/json-schema-core#section-8.2.3.1>).

Decision (implement as specified): when the resolved target and the sibling
members are both mappings and the node has any sibling member, return
`{"allOf": [<resolved>, <siblings-map>]}` — exact conjunction, no key can be
lost. Keep existing behavior for: no siblings (return resolved as today);
boolean targets (`true` → siblings; `false` → `False`); non-mapping target
with siblings → the existing refusal. Do not special-case disjoint keys back
into a merge: `{**a, **b}` is not equivalent to `allOf` when
`additionalProperties` is involved. Current committed documents contain no
`$ref`-with-siblings nodes, so committed rendered output and the corpus must
not change. Update the `resolve_refs` docstring (including the F4 stack
policy below and the round-17 "replacement means conjunction" wording).

### F2 [MEDIUM] Reference Object semantics at every hop, Schema Object semantics only in schema positions

`schema_docs.resolve_reference` (~lines 322–338) strips siblings only from its
initial argument; `resolve_refs` then applies sibling-merge (F1) inside the
referenced subtree. In OpenAPI 3.1 a Reference Object (response, header,
parameter, requestBody, securityScheme positions) carries only `$ref`
(`summary`/`description` are decoration and must not merge), at every hop of a
reference chain
(<https://spec.openapis.org/oas/v3.1.0#reference-object>).

Decision: give the shared walker a position mode. Reference mode (entered via
`resolve_reference`) strips non-`$ref` members at every hop — if a hop target
is itself a Reference Object, strip again and follow. While walking a resolved
node in reference mode, members are document members; descend with reference
mode, except schema positions (the value of a `schema` member, and entries
under `components/schemas`), where Schema Object semantics apply and
sub-`$ref`s keep F1 conjunction rules. Reference mode never merges a sibling
assertion; dangling pointers, unsupported pointers, and cycles keep raising
the existing `ValueError`/`KeyError` classes so the guarded `_resolved_*`
readers in `openapi_check.py` (~lines 1000–1120) turn them into named
findings. Keep `resolve_refs` (schema mode) as the default entry so existing
schema-position callers (`api_validate.py:605,641`, `openapi_check.py:217,238,250`,
`check_local_refs`) are unaffected.

Consumption check: `check_openapi`'s required-response-header path
(`openapi_check.py` ~659–680, via `_resolved_header`) must treat an alias
`required: true` sibling as inert decoration.

### F3 [LOW] Resolve a Security Scheme Reference Object before inspecting fields

`openapi_check.py` authentication check (~lines 1333–1340) assumes
`components.securitySchemes.bearerAuth` is inline; OpenAPI 3.1 permits a
Reference Object there (<https://spec.openapis.org/oas/v3.1.0#components-object>).
Resolve the bearer scheme through reference-mode resolution (F2 mode, or a
guarded `_resolved_*`-style reader) before checking `type`/`scheme`. Missing
target, unsupported pointer, or a reference cycle must return the existing
named failure strings ("is not defined"/not-an-HTTP-bearer style), never an
exception. Preserve the round-17 anonymous-alternative and wrong-scheme
messages exactly.

### F4 [LOW] Independent sibling re-references are not recursion

`resolve_refs` keeps the node's own `$ref` on the cycle stack while resolving
siblings (~lines 294–301), so `{"$ref": A, "allOf": [{"$ref": A}]}` aborts the
CLI with `ValueError: recursive $ref` even though standard validators accept
the document. Fix: evaluate sibling subtrees with the stack as it was *before*
the node's own `$ref` was pushed (a fresh copy; target expansion keeps the
pushed stack). Genuine recursion (target expansion reaching an enclosing
in-flight `$ref`) must still raise. Keep regression coverage for real cycles
and diamond-shaped reuse; correct the round-17 test that pins the false
cycle, and update the round-17 plan's sibling-cycle paragraph in
`docs/plans/0.6-contracts-pr3-review-round17.md` to record the corrected
policy.

### F5 [LOW] Guarded, resolved request body in `check_ota_deferral`

`openapi_check.py` `check_ota_deferral` (~lines 305–307) reads the raw
`requestBody`/`content`. Two failures: a body moved to
`components.requestBodies` + `$ref` reports a false `OTA_DEFERRAL_MISSING`
(the operation checker already resolves it), and `content: null` crashes with
`TypeError` → CLI exit 2. Fix: read `requestBody` through Reference Object
semantics (requestBody is a Reference Object position; a dangling ref yields a
named finding, e.g. `SPEC_COMPONENT_DRIFT`, matching `_resolved_response`
conventions), and guard non-mapping body/content/media-entry shapes into named
document findings (exit 1) — reuse the operation checker's guarded reader
pattern rather than duplicating ad-hoc `.get` chains. Malformed-shape
verdicts keep `OTA_DEFERRAL_MISSING`. Do not define the deferred OTA envelope.
