## Background (verified against the reviewed head)

Finding 1 (`openapi_check.py:1286–1290`). `_requires_bearer` computes
`security = item.get("security", document.get("security", []))` and returns
`any("bearerAuth" in entry for entry in security)`. Security requirements are
alternatives: `[{},{bearerAuth:[]}]` authenticates nobody for the `{}` branch and
still passes. Deleting `components.securitySchemes.bearerAuth` or replacing it
with a query `apiKey` scheme also passes; no code inspects `securitySchemes`.
Call site: `openapi_check.py:171` guards with
`UNAUTHENTICATED_OPERATIONS = {device.pair, backend.get_health_live,
backend.get_health_ready}` (lines 24–29). Committed docs: document-level
`security: [{bearerAuth: []}]` in both contracts; `security: []` on `/pair`
(device line 44) and the two health ops (backend lines 739, 752);
`bearerAuth: {type: http, scheme: bearer, bearerFormat: opaque}` in both.
Spec: `docs/specs/interfaces.md` §2 requires bearer on every device route
except `/pair`.

Finding 2 (`schema_docs.py:262–287`). `resolve_refs` returns
`resolve_refs(_pointer(base, ref), ...)` for any node carrying `$ref` and drops
every sibling key. In JSON Schema 2020-12 (§8.2.3.1) a `$ref` sibling is an
assertion; adding `maxLength: 1` beside the `setup_secret` `$ref` in
`PairRequest` is enforced by a standard Draft 2020-12 validator but silently
ignored by `schema_error_report(resolve_refs(...))`, so body validation
(`api_validate.py:605/641`) and the corpus gate pass a violating fixture.
Audited sibling inventory of the committed docs: exactly one `$ref`-with-siblings
node exists — `backend-v1.yaml` `/components/schemas/CreateTokenRequest/properties/
device_id` carries `$ref` + `description` (an annotation; merging it is
validation-neutral). No `$ref`-with-siblings in `Error`, `Manifest`, headers,
parameters, responses, or media entries, so drift comparisons
(`openapi_check.py:215/236/248`) and regeneration stay byte-identical.

Consistency invariant (round 16, commit `d2b7bab`): the guarded alias follower
at `openapi_check.py:1085–1108` follows `$ref`-with-siblings hops precisely
because `resolve_refs` replaced such nodes wholesale ("the full read the
readability gate ran"); tests at `test_contract_documents.py:1529, 1788–1815`
pin the two reads agreeing. Do not break this: the shallow follower and the
full read must keep certifying the same node the same way for whatever position
they read.

Finding 3 (`api_validate.py:1470–1474`). `_as_int` is `int()` with a
`ValueError` catch, so `+512`, `51_2`, fullwidth `５１２`, and ` 512` all convert.
It is the shared helper for every HTTP integer header rule: Content-Length
(749, 1029, 1682), Upload-Offset (1015, 1439, 1441), Upload-Length (1042),
Retry-After (1115), Limit (1207), declared totals (819), and Range/Content-Range
groups (866, 1325, 1347 — those groups are already `[0-9]`-constrained by the
compiled regexes at lines 47–61). RFC 9110 §8.6 requires `1*DIGIT` (ASCII
digits) for these field values. JSON-body integers go through
`is_json_integer`, not this helper.

## Design decisions (Orchestrator rulings)

1. **Auth (F1).** Replace the `any()` test with an effective-security validator.
   For each protected operation (key not in `UNAUTHENTICATED_OPERATIONS`), all
   of the following must hold or one `SPEC_SECURITY_MISSING` violation is
   reported on `{method} {path}` with a message naming the reason:
   - effective list = operation-level `security` if the operation object carries
     the member, else document-level `security`; must be a non-empty `list`;
   - every element must be a `Mapping` (a non-mapping entry fails);
   - **every** alternative must contain the member `"bearerAuth"` — so `{}` or
     `[{},{bearerAuth:[]}]` or `[{apiKey:[]}]` all fail;
   - `components.securitySchemes.bearerAuth` must exist, be a `Mapping` with
     `type == "http"` (exact) and a string `scheme` whose `casefold()` is
     `"bearer"` (OpenAPI names are case-insensitive for scheme values).
   Unauthenticated operations keep the existing exemption exactly. Baseline must
   stay zero findings for both committed documents.
2. **$ref siblings (F2).** Split the two semantics in `schema_docs.py`:
   - `resolve_refs` becomes schema-aware: on a `$ref` node, resolve the target,
     then merge the node's own sibling keys (all members except `$ref`, each
     recursively resolved) **over** the resolved target:
     `return {**resolved, **siblings}`. If the target is boolean: `True` →
     return the siblings mapping; `False` → return `False` (an unsatisfiable
     assertion conjoins to false). If the target is any other scalar and
     siblings exist, keep today's wholesale return only when there are no
     siblings; with siblings raise `ValueError` naming the `$ref` (a schema
     object cannot conjoin assertions with a non-schema target). Cycle/pointer
     error handling stays as-is.
   - Add `resolve_reference(node, root)` for OpenAPI Reference Object positions
     (resolving a `#/components/responses|parameters|headers/...` node): it
     strips every sibling other than `$ref` before delegating to `resolve_refs`
     (OpenAPI 3.1: non-`summary`/`description` siblings of a Reference Object
     do not augment the target; they must not change gate decisions).
   - Audit each `resolve_refs` call site and route Reference-Object reads to
     `resolve_reference` (known: `openapi_check.py` `_resolve` ~1007, the
     header/response reads at 526/586 and `_read_header_node`; keep the
     readability full read and the shallow follower at 1085–1108 using the same
     semantics for the same position — they already agree by dropping siblings,
     so if the full read for responses becomes `resolve_reference`, the follower
     stays as written). Schema-position reads keep `resolve_refs`
     (`api_validate.py:605/641`, drift renders at `openapi_check.py:215/236/248`,
     and the `Error`/`Manifest`/`$defs` comparisons). Update the docstrings at
     `schema_docs.py:263` and `openapi_check.py:1085–1098` so the stated
     invariant matches the new split, and keep the tests at
     `test_contract_documents.py:1529/1788–1815` proving both reads agree.
3. **HTTP integers (F3).** Tighten `_as_int` to reject anything not matching a
   module-level `re.compile(r"\A[0-9]+\Z")` fullmatch before `int()`; keep the
   `int | None` signature. Every current caller reads an HTTP field or a
   `[0-9]`-constrained regex group, so a strict gate cannot change any
   committed-vector verdict; confirm by the full suite plus regeneration.
