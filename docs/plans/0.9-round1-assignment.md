## Interface contracts (authoritative for both packets)

### `vdog-build-metadata-v1` (produced by Packet A, consumed by Packet B)

File `firmware/.vdog-build-metadata.json`, **gitignored**, regenerated at the
end of every successful normal `pio run -e vdog_xiao_sense_proto`:

```json
{
  "schema": "vdog-build-metadata-v1",
  "firmware_version": "0.2.0-proto",
  "source_sha": "<full 40-hex SHA from VDOG_SOURCE_SHA, else \"local\">",
  "build_id": "<VDOG_BUILD_ID validated per below, else \"local\">",
  "environment": "vdog_xiao_sense_proto",
  "platform": "platformio/espressif32@8.0.0",
  "idf_version": "v6.1.0",
  "esptool_version": "5.4.0"
}
```

- `VDOG_SOURCE_SHA` is accepted only as a full 40-hex object ID; any other
  non-empty value is a hard build failure. `VDOG_BUILD_ID` is accepted only
  as `[A-Za-z0-9._-]{1,64}` (CI sets `pr-<n>-<sha12>`, `main-<sha12>`);
  anything else fails the build. Unset/absent ⇒ local identity
  `source_sha="local"`, `build_id="local"`. No environment value is ever
  emitted as C-preprocessor or shell text.
- `firmware_version` must match `vdog_core.h` (`0.2.0-proto`).

### `vdog-flash-layout-v1` (produced by Packet B `export_flash_layout.py`)

```json
{
  "schema": "vdog-flash-layout-v1",
  "target": "esp32s3",
  "flash_size_bytes": 8388608,
  "upload": {"flash_mode": "dio", "flash_size": "8MB", "flash_freq": "80m"},
  "segments": [
    {"role": "bootloader",        "file": "images/bootloader.bin",        "offset": 0,      "size": 0, "sha256": "..."},
    {"role": "partition_table",   "file": "images/partitions.bin",        "offset": 32768,  "size": 0, "sha256": "..."},
    {"role": "ota_data_initial",  "file": "images/ota_data_initial.bin",  "offset": 61440,  "size": 0, "sha256": "..."},
    {"role": "application",       "file": "images/firmware.bin",          "offset": 131072, "size": 0, "sha256": "..."}
  ]
}
```

Role→actual-file resolution is from the PlatformIO build directory
(`.pio/build/vdog_xiao_sense_proto/`): `bootloader.bin`, `partitions.bin`,
`ota_data_initial.bin`, `firmware.bin`, cross-checked against the builder's
generated `flasher_args.json`/`flash_args` and the partition CSV. Missing,
unknown or conflicting outputs are errors — never basename-globbing, never a
stale fallback, never the embedded test runner from `pio test`.

### Release manifest

`firmware-release-v1` per master plan §4 (product/hardware class, target
`esp32s3`, expected flash bytes, board/environment, firmware version, full
source SHA, PR head/base or main identity, build ID, tag (main only), run
ID/attempt, toolchain versions, partition-table hash, flash parameters, image
roles/offsets/sizes/hashes, package format version, and
`release_channel: "prototype"`, `hardware_verified: false`,
`recording_available: false`, `device_ota_available: false`). Every payload
file gets size+SHA-256 coverage; `manifest.json` and `SHA256SUMS` are excluded
from self-referential hashing exactly as §4 specifies.
