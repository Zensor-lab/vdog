# vdog firmware release notes

This bundle installs the vdog `0.2.0-proto` prototype firmware onto a **Seeed
Studio XIAO ESP32S3 Sense** (8MB flash / 8MB octal PSRAM) over USB serial. It
is packaged deterministically by CI from one exact commit and validated before
publication.

This file is the release-notes source that CI packages into every bundle as
`RELEASE_NOTES.md` (`--release-notes-md docs/release-notes-template.md`). It
deliberately carries no per-build values: the exact identity of a given bundle
lives in its own `VERSION.json` and `manifest.json`, and the Release body
generated by `tools/firmware/publish.py` prints it alongside the asset digests.

## Status of this release (must stay visible)

| Field | Value |
| --- | --- |
| `release_channel` | `prototype` |
| `hardware_verified` | `false` — no physical-device verification evidence |
| `recording_available` | `false` — the bootstrap does not record |
| `device_ota_available` | `false` — no device-side OTA |

Published as a GitHub **pre-release** and never flagged as the repository's
"latest" release. It provides no camera, SD, recording, radio or app feature,
and no signed-OTA guarantee. Evidence for these builds is BUILD/HOST only;
installation onto identified hardware is a separate, still-deferred gate.

## What the bundle contains

```text
INSTALL.md  RELEASE_NOTES.md  VERSION.json  manifest.json  SHA256SUMS
LICENSE  THIRD_PARTY_NOTICES.md
images/     bootloader.bin  partitions.bin  ota_data_initial.bin  firmware.bin
flash/      partitions.csv  flash-layout.json  flash_args
install.py  install.sh  install.ps1  requirements-installer.lock
```

Four validated flash segments are written, at the offsets generated by the
pinned builder and recorded in `flash/flash-layout.json`: bootloader at
`0x0`, partition table at `0x8000`, initial OTA data at `0xf000` and the
application at `0x20000` (8MB flash, DIO, 80m). NVS, the `storage` partition,
the SD card and all security fuses are untouched, and there is no erase path.

## Where your exact identity lives

Open `VERSION.json` (or `manifest.json`) in the extracted folder:

| Field | Meaning |
| --- | --- |
| `build_id` | `main-<sha12>` for a Release, `pr-<number>-<sha12>` for a PR artifact, `local` for a private build |
| `source_sha` / `source_sha_short` | the full and 12-character commit identity built |
| `tag` | `firmware-main-<sha12>` for Releases (`null` for PR and local builds) |
| `firmware_version` | semantic version from the firmware source |
| `ci_run_id` / `ci_attempt` | the Actions run that produced this bundle |

The firmware prints the same identity at startup:

```text
I (xxx) vdog: build identity: build_id=main-<sha12> source_sha=<sha12>
```

## Install

Follow `INSTALL.md` in this bundle (also
[docs/release-installation.md](release-installation.md) in the repository):
verify the digest, run `./install.sh check`, then `ports`, `plan`, `inspect`
and finally `install` with an explicit `--port` and your consent. You need
Python 3.12 and `uv` on the host — PlatformIO, ESP-IDF and a source clone are
not required, and the installer never touches a global Python environment.

**Unplug the battery pack before USB servicing.**
